# HMI 函数注释规范

## 适用范围

在 `.c` / `.h` 源文件中新增或修改函数时，必须遵循本规范添加/更新函数注释头。

## 函数注释模板

```c
/*********************************************************************
 * 函 数 名: ModuleName_ActionObject
 * 函数入参: uint32 ulBuff	bit[7:0]=含义, bit[15:8]=含义
 * 函数出参: 无
 * 返 回 值: void
 * 功能描述: 一句话描述函数功能
 * 说明: 补充说明、设计意图、注意事项（可选但推荐）
 ***********
 * 修改历史:
 *   1.修改作者: sjh
 *     修改日期: 2026年07月04日
 *     修改描述: 新函数
 **********************************************************************/
void ModuleName_ActionObject(uint32 ulBuff)
{
}
```

### 带指针参数的函数模板

```c
/*********************************************************************
 * 函 数 名: ModuleName_ProcessData
 * 函数入参: DATA_CB *pDataCB	数据结构体指针
 * 函数出参: 无
 * 返 回 值: void
 * 功能描述: 处理数据下发指令
 * 说明: 调用前需确保pDataCB已初始化
 ***********
 * 修改历史:
 *   1.修改作者: sjh
 *     修改日期: 2026年07月04日
 *     修改描述: 新函数
 **********************************************************************/
void ModuleName_ProcessData(DATA_CB *pDataCB)
{
	// 参数合法性检验
	if (NULL == pDataCB)
	{
		return;
	}

	/* 后续业务逻辑 */
}
```

## 字段说明

| 字段 | 必须 | 说明 |
|------|:----:|------|
| `函 数 名` | ? | 函数全名，与声明一致 |
| `函数入参` | ? | 类型+参数名+含义；无参写 `无`；多参逐行列出或用 Tab 分隔 |
| `函数出参` | ? | 说明输出参数含义，无输出写 `无` |
| `返 回 值` | ? | 返回值类型，`void` 函数写 `void` |
| `功能描述` | ? | 一句话概括函数作用 |
| `说明` | 推荐 | 补充说明如设计意图、调用条件、像素尺寸、数据流向等 |
| `***********` | ? | 分隔线（11个星号），必须紧贴上一行 |
| `修改历史` | ? | 必须包含至少一条记录 |
| `修改作者` | ? | 作者名缩写（如 `sjh`、`ZJ`） |
| `修改日期` | ? | `YYYY年MM月DD日` 格式（中文年月日） |
| `修改描述` | ? | 如"新函数"或具体修改内容 |

## 格式细节

1. **注释块边界**：以 `/********************************...` 开始，` **...**/` 结束，星号对齐
2. **标签缩进**：` * ` 开头，`空格+星号+空格` 后跟中文标签和冒号
3. **修改历史编号**：使用 `*   1.`、`*   2.` 等缩进3空格编号
4. **子字段缩进**：`修改作者`/`修改日期`/`修改描述` 前缩进 5 个空格（`*     修改作者:`）
5. **中文内容**：所有标签和描述使用中文
6. **指针校验**：函数入参包含指针类型时，函数体首行必须进行 NULL 指针校验：
   ```c
   // 参数合法性检验
   if (NULL == pPtr)
   {
       return;
   }
   ```
   若函数有非 void 返回值，return 需带上对应的无效值（如 `return FALSE;` 或 `return;`）
7. **逻辑运算括号**：涉及 `||` 或 `&&` 运算时，每个子条件必须用括号包裹，避免优先级歧义：
   ```c
   // 正确写法
   while ((nameLen < HUDNAV_ROAD_NAME_MAX_LENGTH) && (paramCB.runtime.hudnav.roadName[nameLen] != '\0'))
   if ((a > 0) || ((b < 10) && (c != 0)))
   
   // 错误写法
   while (nameLen < HUDNAV_ROAD_NAME_MAX_LENGTH && paramCB.runtime.hudnav.roadName[nameLen] != '\0')
   if (a > 0 || b < 10 && c != 0)
   ```
   嵌套逻辑时，外层运算符的左右子表达式各用一对括号，内层同理递进

```c
 * 函数入参: uint32 ulBuff	bit[7:0] = popupFlag(弹窗显示标志), bit[15:8] = selectOpt(0=cancel,1=confirm)

 * 返 回 值: void
 * 功能描述: 日行灯设置确认弹窗
 * 说明: 灰色底色330x141 + 四角圆角图片 + 提示文字 + Confirm按钮

 * 修改历史:
 *   1.修改作者: sjh
 *     修改日期: 2026年07月04日
 *     修改描述: 新函数
```
```c
 **********************************************************************/
```

## 检查清单

- [ ] 注释块是否以 `/******...` 格式正确闭合？
- [ ] `函 数 名` 是否与函数声明一致？
- [ ] `函数入参` 是否列出所有参数及其含义（含bit位说明）？
- [ ] `函数出参` / `返 回 值` 是否填写？
- [ ] `功能描述` 是否一句话清晰概括？
- [ ] `说明` 是否补充了关键细节（如坐标尺寸、调用条件）？
- [ ] `***********` 分隔线是否紧贴上一行（11个星号）？
- [ ] `修改历史` 是否含至少一条有效记录？
- [ ] `修改日期` 是否为 `YYYY年MM月DD日` 格式？
- [ ] 入参含指针时，函数体首行是否有 `if (NULL == pPtr) { return; }` 空指针校验？
- [ ] `||` / `&&` 运算符的每个子条件是否用括号包裹？
